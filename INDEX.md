## 2. Les décisions déjà prises

Ne les rediscute pas sans le dire explicitement.

| Sujet | Décision | Détail |
|---|---|---|
| Montants | entier de **cents**, signé ; arrondi = affichage seulement | `CLAUDE.md` §11 |
| Saisie d'un montant | la **chaîne** saisie traverse jusqu'à la Server Action, la conversion en cents est faite par le `transform` zod partagé | `CLAUDE.md` §11 |
| Dates de transaction | date civile sans heure, typée **chaîne** dans le domaine | `docs/lot-m0.md` §2.6 |
| Identifiants | `cuid()` partout, sans exception | `docs/lot-m0.md` §2.3 |
| Base de données | PostgreSQL 17 | `docs/plan.md` §8.1 |
| **Hébergement** | **Docker** sur un hôte existant, stack `budgapp-db` — pas de machine dédiée | `docs/lot-m0.md` §1 |
| Extensions PostgreSQL | `pg_trgm` et `unaccent`, créées par une **migration Prisma dédiée** (`prisma/migrations/20260914213000_pg_trgm_unaccent/`), **pas** déclarées dans le `datasource` Prisma | `docs/lot-m1.md` §4.3, journal §5 (2026-09-14) |
| Budget | modèle **d'enveloppes avec report** (trois modes), cibles paramétrables, reste à assigner — remplace le montant fixe sans report | `docs/decision-modele-budget.md`, `docs/modele-budget-prevision.md` §2 |
| Virement | paire de transactions symétriques liées, exclue du budget des deux côtés — pas d'enveloppe de paiement de carte | `docs/modele-budget-prevision.md` §2.7 |
| Ventilation | auto-référence `Transaction.parentId`, pas une table séparée | `docs/lot-m0-revision.md` §3.2 |
| Cadences | 12 valeurs (le jeu de YNAB), dont `PONCTUEL` (occurrence unique) | `docs/lot-m0-revision.md` §3, schéma `enum Cadence` |
| Estimateur de prévision par défaut | médiane des 6 derniers mois | `docs/modele-budget-prevision.md` §5 |
| Incertitude | quantiles du **total** mensuel, pas somme des quantiles | `docs/modele-budget-prevision.md` §6 |
| Récurrences | occurrences attendues + liaison explicite, jamais une ressemblance | `docs/modele-ingestion-recurrences.md` §4 |
| Solde | ancrages datés + réconciliation + transaction d'ajustement | `docs/modele-ingestion-recurrences.md` §5 |
| Entrées de données | un pipeline, trois adaptateurs (copier-coller, fichier, agrégateur) | `docs/modele-ingestion-recurrences.md` §1 |
| **Profil d'import** | objet du domaine, **non persisté** en M1 ; le modèle `ImportProfile` attend CSV/OFX en M9 | `docs/lot-m1.md` §3.1 |
| **Règles en conflit** | la priorité départage ; **à priorité égale, rien n'est appliqué** et la ligne passe en revue | `docs/lot-m1.md` §3.2 |
| **Type d'opération** | séparé du marchand par un séparateur du profil (`operation.separateur`) ; la description est celle du marchand ; non persisté en M1, **persisté depuis M2** (`Transaction.typeOperation`, hors empreinte, règles et dédoublonnage) | `docs/lot-m1.md` §5.8, `docs/lot-m2.md` §3.1 |
| **Fragments sans date** | masqués à l'affichage de la revue, jamais au parser ; garde-fou : contrôle du total du relevé | `docs/lot-m1.md` §5.9 |
| `Payee.categorieParDefautId` | **appliqué** — renommé en `sousCategorieParDefautId`, relation Prisma déclarée vers `Subcategory` (`onDelete: SetNull`) | `docs/lot-m1.md` §3.3 |
| Agenda | flux ICS dans les deux sens, pas l'API Google | `docs/modele-budget-prevision.md` §10 |
| Erreurs serveur | `ActionResult` typé, pas de `throw` métier | `CLAUDE.md` §6 |
| Navigation | barre horizontale, pas de barre latérale ; huit onglets à terme, six dans la coquille de M0 | `CLAUDE.md` §10 |
| Multi-utilisateur | préparé (`ownerId` partout), pas implémenté | `docs/plan.md` §2 |
| Paquets | npm | `docs/plan.md` §8.3 |
| CI | aucune ; hook `pre-push` local qui lance `npm run check` | `docs/lot-m0.md` §2.1 |
| **Git** | une branche par lot, fusion par demande de fusion en `--no-ff`, étiquette par lot ; en mode pilote : fusion locale `--no-ff` + étiquette, sans demande de fusion sur la forge (`docs/pilotage/gouvernance.md` §6) | `CLAUDE.md` §14 |
